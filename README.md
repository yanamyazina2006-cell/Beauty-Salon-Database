# Beauty-Salon-Database
# База данных сети салонов красоты

**Проектная работа · Системный аналитик/проектировщик БД**

## О проекте
Реляционная база данных для автоматизации деятельности сети салонов красоты. Система охватывает учёт клиентов, сотрудников, филиалов, услуг, записей на приём и платежей.

## Что сделано
- Провела анализ предметной области, выделила **12 сущностей** (клиенты, сотрудники, филиалы, услуги, записи, платежи и др.).
- Разработала **концептуальную ER-модель** в нотации IDEF1X.
- Спроектировала **даталогическую модель** с 12 таблицами: определила атрибуты, типы данных, ограничения целостности (PK, FK, UNIQUE, NOT NULL, CHECK).
- Составила **словарь данных** с описанием всех атрибутов.
- Реализовала базу данных в **MySQL**: DDL-скрипты создания таблиц, тестовые данные.
- Написала **SQL-запросы** разных уровней сложности: CROSS JOIN, INNER JOIN, LEFT JOIN, GROUP BY / HAVING, CASE, вложенные подзапросы, VIEW.
- Разработала **2 триггера** и **2 хранимые процедуры** для автоматизации бизнес-логики.

## Артефакты

### Моделирование
- `concept/conceptual-model.png` — концептуальная ER-модель (IDEF1X)
- `concept/logical-model.png` — даталогическая модель БД
- `concept/data-dictionary.md` — словарь данных (12 таблиц, атрибуты, типы, ограничения)

### SQL
- `sql/ddl.sql` — скрипт создания таблиц с ограничениями и связями
- `sql/insert-data.sql` — скрипт заполнения тестовыми данными
- `sql/queries.sql` — SELECT-запросы (CROSS JOIN, INNER JOIN, LEFT JOIN, GROUP BY/HAVING, CASE, подзапрос, VIEW)
- `sql/triggers.sql` — 2 триггера:
  - `limit_appointments_per_employee` — ограничение 5 записей на сотрудника в день
  - `set_registration_date` — автозаполнение даты регистрации клиента
- `sql/procedures.sql` — 2 хранимые процедуры:
  - `GetClientAppointments` — история визитов клиента
  - `GetEmployeeScheduleByDate` — график работы сотрудника на дату
- `sql/views.sql` — представление `view_client_status` (сегментация клиентов по уровню лояльности)
